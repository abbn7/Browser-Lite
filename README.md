# dot / Browser Lite

مساعد تصفح شخصي بواجهة عربية للموبايل: متصفح Chromium مباشر، مهمة واحدة، استلام تحكم، موافقات على الأفعال، وحفظ التقدم. الواجهة خفيفة بدون إطار JavaScript أو خطوة npm إضافية؛ الخدمة تستخدم Browser-use بدل محرك إيجنت مكتوب من الصفر.

## التشغيل على Railway

1. فك الحزمة وارفع محتويات هذا المجلد إلى مستودع GitHub خاص.
2. Railway → New Project → Deploy from GitHub repo → اختر المستودع. Dockerfile وrailway.toml جاهزان.
3. أضف Volume واربطه بالمسار `/data`. يشغل التطبيق عملية واحدة فقط وReplica واحدة.
4. أضف Variables التالية، ثم Deploy:

| المتغير | القيمة |
|---|---|
| `APP_PASSWORD` | كلمة مرور قوية من 12 حرفًا على الأقل |
| `LLM_PROVIDER` | `agent_router` أو `openrouter` أو `google` |
| `LLM_API_KEY` | مفتاح صالح من المزوّد؛ لا يوضع في الكود |
| `LLM_MODEL` | معرف موديل متاح في حسابك |
| `LLM_BASE_URL` | Agent Router: `https://agentrouter.org/v1`؛ OpenRouter: `https://openrouter.ai/api/v1`؛ احذفه مع Google |
| `DATA_DIR` | `/data` |

5. Settings → Networking → Generate Domain. افتح الرابط عبر HTTPS وسجّل الدخول بكلمة مرور التطبيق؛ لا تحتاج اسم مستخدم.
6. افتح الإعدادات داخل التطبيق واضغط «اختبر اتصال الموديل». بعدها افتح موقعًا أو اكتب مهمة.
7. في Safari على الآيفون: مشاركة → إضافة إلى الشاشة الرئيسية.

**Agent Router:** تم التحقق من المفتاح المرسل عبر Codex CLI الرسمي ونجح، ونجح `gpt-6.1-sol` في إرجاع JSON منظّم. طلبات HTTP المباشرة أعادت `unauthorized_client_error`؛ لذلك يستخدم التطبيق افتراضيًا النقل `AGENT_ROUTER_TRANSPORT=codex` وبروتوكول Responses. المفتاح غير مضمن في الحزمة؛ أضفه إلى Railway Secrets. اختبار الاتصال داخل التطبيق يستخدم نفس النقل.

لا يوجد رابط نشر عام أو زر قالب Railway منشور؛ لم يتوفر مستودع منشور/حساب Railway مخوّل لإنشائه. الخطوات السابقة تنشر نفس الحزمة دون تغيير الكود.

## تشغيل محلي بدوكر

```sh
cp .env.example .env
# عدّل .env وضع كلمة المرور والمفتاح والموديل
# لإنشاء كلمة مرور: python -c 'import secrets; print(secrets.token_urlsafe(24))'
docker compose up --build -d
```

افتح `http://localhost:8000`. هذا الربط محلي فقط؛ استخدم HTTPS reverse proxy إذا أردت الوصول من أجهزة أخرى. Compose يحدد 512MiB وCPU واحد؛ عدّل الحد عند الحاجة، ولا تستخدم swap لإخفاء فشل الاختبار.

## الاستخدام

- **افتح**: متصفح يدوي من غير استدعاء موديل.
- **ابدأ المهمة**: رابط + تعليمات؛ يمنع التطبيق وجود مهمتين تعملان معًا.
- **الوضع الافتراضي**: يتطلب موافقة قبل كل أداة تغير الصفحة بالنقر أو الكتابة. الموافقة تخص خطوة واحدة.
- **السماح بالنقر والكتابة للمهمة**: وضع تلقائي باختيار صريح. قد ينفذ تغييرات داخل المواقع؛ لا تستخدمه للمهام الحساسة. طلبات الموافقة الذكية في هذا الوضع تعليمات للموديل وليست ضمانًا لتصنيف كل فعل.
- **استلم التحكم**: يوقف تنفيذ الإيجنت أولًا. انقر الحقل داخل الصورة، واكتب في حقل التحكم ثم اضغط «اكتب». أزرار ↑ ↓ للتمرير و↵ للإدخال.
- بيانات الإدخال اليدوي لا تُسجل ولا تُرسل مباشرةً للموديل. بعد الاستئناف يمكن للموديل رؤية الصفحة الحالية؛ لا تترك أسرارًا ظاهرة عليها.
- **استكمل**: يبدأ دفعة جديدة من حالة الصفحة والتقدم المحفوظ، وليس إعادة إرسال أفعال قديمة.
- كابتشا/2FA/تسجيل دخول: استلم التحكم وأكملها بنفسك، ثم استأنف. لا إخفاء مضمون للأتمتة ولا خدمة حل كابتشا مضافة.
- بيانات المواقع وCookies محفوظة في بروفايل خاص على `/data`. «مسح الجلسات» يزيل البروفايل؛ ليس جلسة تطبيقك.
- المهمة تستمر عند إغلاق شاشة الهاتف طالما الخدمة تعمل. بعد إعادة تشغيل الخدمة تصبح المهمة متوقفة للمراجعة. نماذج غير محفوظة وحالة الذاكرة الداخلية للصفحة لا تُستعاد بالضرورة.

## الحدود الافتراضية

`MAX_STEPS=100`، `TASK_TIMEOUT_SECONDS=3600` لكل دفعة. يمكن الاستكمال بعد الحد. `USE_VISION=true`؛ يمكن تعطيله لموديل نصّي. العرض صور JPEG بمعدل أقصى يقارب 1.4 إطار/ثانية؛ ليس بث فيديو عالي الإطارات. الصفحة الداخلية 390×740؛ يمكن تكبير مساحة العرض. لا يوجد تغيير viewport Desktop في هذه النسخة.

المتصفح يُغلق بعد دقيقتين دون استخدام وعندما لا توجد مهمة نشطة. عرض الصفحة المفتوح يُعد استخدامًا. تحفظ الخدمة آخر 20 مهمة في واجهة API؛ لا توجد لوحة سجل منفصلة. النتائج تظهر في الشاشة نفسها.

الملفات القابلة للتنزيل: 10MB للملف؛ تنظيف دوري كل 30 ثانية للملفات الأقدم من 24 ساعة أو الإجمالي فوق 50MB. هذه حدود احتفاظ، وليست حدًا صارمًا لحجم البيانات أثناء تنزيل جارٍ. راقب التخزين للمواقع التي تنزّل ملفات ضخمة.

لا يوجد سقف مالي دقيق داخل التطبيق. اضبط سقف الإنفاق في حساب المزوّد؛ حدود الخطوات والوقت لا تضمن مبلغًا محددًا.

## الحماية والتشغيل

- واجهات API والصور والملفات تحتاج جلسة دخول. Cookie من نوع HttpOnly وSameSite Strict وSecure عبر HTTPS، مع Origin وCSRF للتحكم.
- جلسة التطبيق تنتهي بعد 24 ساعة أو إعادة تشغيل الخدمة؛ جلسات المواقع تبقى على الـVolume.
- CDP غير منشور خارج الحاوية. وكيل خروج محلي يتحقق من عناوين DNS ويمنع الوجهات الخاصة وmetadata والمنافذ غير 80/443. لا يسمح الإيجنت بزيارة `file:` أو بتشغيل كود اعتباطي أو رفع ملفات محلية.
- التطبيق لمستخدم واحد موثوق، وليس خدمة متعددة المستأجرين. الموقع قد يطلب التحقق أو يرفض متصفح السيرفر.
- ملفات الجلسات على الـVolume حساسة. ليست مشفرة بمفتاح مستقل داخل هذا التطبيق؛ صلاحياتها محلية وتخضع لأمان منصة الاستضافة. لا تنشر الـVolume أو تحفظه في Git.
- الحاوية تبدأ تهيئة ملكية `/data` ثم تسقط صلاحياتها إلى UID 10001 قبل تقديم الطلبات. Chromium sandbox معطل افتراضيًا لتوافق الحاويات؛ تبقى عزلة الحاوية ضرورية. يمكن تفعيل `CHROMIUM_SANDBOX=true` على مضيف يدعمها.
- حزمة Browser-use لها اعتماديات كثيرة، ويتضمن Docker الآن ملف Codex التنفيذي الرسمي المثبّت بالإصدار 0.163.0 لتوافق Agent Router؛ لا يحتاج تثبيت Node.js في الإنتاج. صورة Docker أكبر بكثير من الواجهة. انظر تقرير الاختبارات للأحجام الفعلية.

## الاختبارات

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt pytest==9.0.2
pytest -q tests/test_core.py
playwright install chromium
PYTHONPATH=. CHROMIUM_SANDBOX=false python tests/browser_integration.py
```

`tests/browser_integration.py` يستخدم Chromium وBrowser-use فعليين مع موديل محدد النتائج لاختبار التوصيل، وليس قياسًا لجودة الذكاء. اختبارات `container_app.py` و`container_smoke.py` مخصصة للاختبار ولا تدخل صورة الإنتاج.

لاختبار واجهة خدمة شغالة:

```sh
TEST_BASE_URL=http://localhost:8000 TEST_APP_PASSWORD='<كلمة المرور>' TEST_OUTPUT_DIR=./artifacts python tests/ui_smoke.py
```

يجب توفير متغيرات الشبكة المعتادة إذا كنت داخل بيئة proxy. `BROWSER_UPSTREAM_PROXY` اختياري لربط خروج المتصفح بوكيل المؤسسة. `BROWSER_CA_CERT` اختياري لمسار شهادة مؤسسة موثوقة؛ لا تستخدمهما على Railway العادي ولا تعطل TLS.

راجع [VALIDATION.md](VALIDATION.md) للنتائج والحدود.

## المراجع والترخيص

[Browser-use](https://github.com/browser-use/browser-use) هو المحرك، و[Playwright](https://github.com/microsoft/playwright) لتوفير Chromium والاختبارات. [Liquid Glass React](https://github.com/rdev/liquid-glass-react) مرجع بصري تقني؛ لم ننسخ مكوناته ولم نضف اعتماده بسبب دعم Safari الجزئي. الزجاج منفذ بـCSS. [Railway](https://railway.com/pricing) يحدد رصيد الاستهلاك وحدود الخطة.

كود التطبيق MIT؛ تراخيص الاعتماديات والمتصفح وCodex مستقلة. انظر SOURCES.md ومجلد licenses.

## تحديث التصميم وربط Agent Router

الثيم يستخدم نفس قيم AMOLED و`glass` و`glass-strong` و`glass-chip` من مستودع `abbn7/glass-morphic-brilliance` عند commit `d1dab0a`، مع تركواز/وردي وخط IBM Plex Sans Arabic محلي. لا يُحمّل WebGL أو مشهد البورتفوليو ثلاثي الأبعاد.

Codex يعمل كمحوّل للموديل فقط: محادثة Browser-use وصور الصفحة → Responses عبر CLI → JSON مخطط → تنفيذ الأدوات بواسطة التطبيق. Shell وMCP وإضافات المتصفح في CLI معطلة، ويُستخدم مجلد مؤقت و`--ephemeral` و`--ignore-user-config`. تُنظَّف الملفات المؤقتة وتُنهى العملية عند الإلغاء أو انتهاء المهلة. ليس CLI أداة لتنفيذ أوامر المستخدم. المفتاح يُمرّر في بيئة العملية ولا يُكتب في ملف الإعدادات.

`MODEL_TIMEOUT_SECONDS=120` حد الاستدعاء الواحد، و`CODEX_BINARY` اختياري لتحديد مسار binary محلي. ترك `AGENT_ROUTER_TRANSPORT=codex` هو المسار الذي تم التحقق منه. `chat_completions` متاح فقط إذا سمح مزوّدك بطلبات HTTP المباشرة. OpenRouter وGoogle يستمران عبر SDK دون CLI.

تشغيل محلي بدون Docker يحتاج تثبيت Codex 0.163.0 إضافة إلى متطلبات Python؛ Docker يثبته تلقائيًا من حزمة npm الرسمية مع فحص SHA-512.

نجح الاختبار النهائي بموديل Agent Router الحقيقي `gpt-6.1-sol` داخل حاوية 512MiB وCPU واحد: مهمة قراءة موقع مكتملة، وأعلى ذاكرة مرصودة 351.5MiB. الواجهة مع الخطوط والأيقونات حوالي 168KiB غير مضغوطة، وصورة Docker حوالي 1.54GB على القرص. هذه نتيجة موقع بسيط ولا تضمن كل المهام الطويلة أو المواقع الثقيلة.
